# 채용 예정 포지션 — 업무 지도에서 뽑는 규칙

`collect_org.mjs` 가 `my-work-map.md` 에서 후보를 뽑는다. 결과는 **제안**이며 사용자가 확인한 것만 그린다.

## 어디서 뽑나 (순서)

1. `## 상위 3개 업무` 의 번호 항목 `1. **업무명** — …` → 이유 "업무 지도 · 상위 업무"
2. `## 업무 표` 에서 위임 희망도 **4 이상**인 행 → 이유 "업무 지도 · 위임 희망도 N"
3. `- 맡기고 싶은 일: a, b, c` → 쉼표·가운뎃점·슬래시로 나눠 각각 → 이유 "업무 지도 · 맡기고 싶은 일"

중복 제거, 최대 8개, 제목 14자·이유 24자로 자른다. 이모지는 역할 단어로 추측(리서치 📊 · 글 ✍️ · 코딩 💻 · 디자인 🎨 · QA 🔍 · 마케팅 📣 · 고객/응대 💬 · 영상 🎬 · 재무/정산 🧾 · 주문/쇼핑 🛍️ · 교육 📘 · 메일 📮 · 일정 📅, 없으면 ✨).

## 이미 맡은 직원이 있으면 뺀다

후보 제목의 2글자 이상 단어가 기존 직원의 역할·이름에 들어 있으면 제외하고 `notes` 에 "n개 제외"라고 적는다. 예: 직원 「플로라 · 예약 꽃다발」이 있으면 후보 "예약 꽃다발 관리"는 빠진다. 오탐이 있을 수 있으니 사용자 확인 때 "빠진 후보"도 한 줄로 말해 준다.

## 업무 지도가 없을 때

`notes` 에 적히고 `planned` 가 빈다. 사용자에게 묻는다: "앞으로 비서에게 맡기고 싶은 일 2~3개만 알려 주실래요? 빈 책상에 '채용 예정'으로 붙여 둘게요." 답을 org.json 의 `planned` 에 넣는다.

## 발표에서 쓰는 법

채용 예정 태그는 "다음 단계"를 말하는 장치다. 2주차(메일/카톡 연결), 3주차(콘텐츠 자동화), 4주차(팀 운영) 과제와 연결해 "이 자리는 3주차에 채워요"라고 말하면 수업 로드맵이 사무실 그림 하나로 보인다.
